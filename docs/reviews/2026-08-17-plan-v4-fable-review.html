Findings

P0A · Node 22-only breaks the operator's own machine.
v4 §2 non-goals: "The first release targets Node 22 only"; Phase 6.1 narrows engines to >=22.17.0 <23 and adds a launcher check that "rejects a mismatched Node major/ABI". Facts: the Rust room resolves node.exe from PATH (host_process.rs:1063); the PATH Node on this machine is v24.18.0; the current package.json engines already allow >=24.2.0; the room runs on 24 today. Under v4 the finished m0irai would refuse to start here.
Fix: the proven runtime is the one the operator runs — Node 24.x — with the engines range kept as-is; the release records the Node major/ABI it was built with and the launcher warns on mismatch (a hard reject on a range that already works is a ratchet in the wrong direction). CI may add 22 later.
P1 · scopeB · v4 folds a hardening program into the clean-up.
New surface not required to make the folder clean and running: hostile-session-ID grammar + symlink/junction containment matrix (2.4), atomic transcript writes (2.5), an app-wide ACP/PTY/ConPTY process registry with hung/cold-child fixtures (5.6–5.7), an exactly-once close state machine (5.3), launcher ABI reject (6.1), clean-Windows-VM proof (6.5), license disposition (6.3), acceptance schema (6.4), both-OS Rust CI. These are real findings — most are latent V2 defects that exist today, unchanged by the extraction — but two things follow from bundling them: (1) "done" is held hostage to a program of unknown length; (2) 2.4/2.5 land before the first commit, so commit 1 is no longer a pristine import + proof harness — the provenance diff gets muddy.
Fix: two milestones. M1 — standalone runs: import, cuts, digest wiring, the PTY-drain relocation the cli cut forces, oracle, release script, fresh-clone proof on this machine, private repo. M2 — public-ready: everything above plus README/licenses, then the hardening items as their own spec'd wave. v4's Phase 2.4/2.5 and 5.6–5.7 move to M2. The operator gets to run m0irai daily at M1.
P1C · "WORK history is never pushed" = zero off-machine backup during days of cutting.
Invariant 10 and Phase 1 forbid any remote for WORK. This session has already lost work to a power outage and to usage cut-offs. The invariant that matters is WORK never becomes FINAL history / never goes public. Fix: push WORK to a private scratch remote (CodeZer0-vibe/m0irai-work), deleted after FINAL is accepted.
P1D · "exactly 20 Rust packages" is a target where it should be a measurement.
Phase 4.1 prunes all 4 pager dev declarations (xai-grok-pager-pty-harness, xai-grok-test-support, +agent/shell) to land on 20 — but the JUDGE already measured that the pty-harness "backs 16–21 test files" and recommended, under approach B, simply keeping ptyctl, the harness and test-support. Cutting those tests to hit a round number is a quality cut. Also: flipping the pager's default to [] changes what cargo test --workspace compiles — some tests behind grok-runtime may stop building; that is a Phase 4 measurement, not a plan-time fact.
Fix: prune the 19 optional product edges (16 pager + 3 pager-render); keep every dev edge whose tests still compile under the retained features; the package count is whatever falls out (likely 22) and is pinned after measurement.
noteE · v4 has been reviewed only by its author. §1 ends: "A bounded independent re-check of the corrected v4 found no unresolved P0/P1" — that re-check was codex on codex. This page is the first outside read. Given A–D, I would not re-run the six-reviewer machine; a v5 delta is small and every structural claim is now checked against the tree.
noteF · Premature supersede. Codex already edited v3's header to "superseded — do not execute" before anyone accepted v4 (uncommitted). Harmless; hold the commit until v5.
noteG · ZER0_HERMETIC=1 is a new production switch (disables provider acquisition for the oracle). Acceptable minimal seam; must be documented next to ZER0_DIGEST_FAKE and guarded the same way so it cannot leak into a real run.
