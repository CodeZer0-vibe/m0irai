## 2. The Common Adapter Abstraction

All three agents collapse onto one Node interface. The shapes differ; the **lifecycle is identical**: spawn long-lived native agent → read event stream → on each proposed action, surface ALLOW/DENY to operator → send decision back on the same correlation id → agent's writes land in an isolated worktree → tower reviews diff → merge on accept.

```ts
// The ONE interface a control tower needs.
interface NativeAgentAdapter {
  // Spawn the agent as a long-lived, FULL-NATIVE, MEDIATED child (never one-shot, never yolo/bypass).
  // worktreePath becomes the agent's cwd; all writes are confined there until merge.
  start(opts: {
    worktreePath: string; // git worktree add ../wt-<id> -b agent/<id>  (created out-of-band)
    task: string;
    cleanEnv: NodeJS.ProcessEnv; // MUST strip CLAUDE_CODE_* nesting markers (claude) / provider keys (all)
  }): Promise<AgentSession>;

  // Newline-delimited event stream. One emitted union per protocol object.
  events(): AsyncIterable<AgentEvent>;
  // 'message' | 'thinking' | 'tool_proposed'(REQUIRES decision) | 'tool_result' | 'turn_done' | 'usage' | 'error'

  // Called by the tower for EVERY 'tool_proposed'. The agent's turn BLOCKS until this resolves.
  // decision: 'allow' | 'deny'  (NOTE: 'modify' is NOT universally supported — see §3)
  decide(req: ToolProposal, decision: ApprovalDecision): Promise<void>;

  steer(text: string): Promise<void>; // the ONLY portable "alter the action" path: deny + re-instruct
  interrupt(): Promise<void>;
  close(): Promise<void>; // MUST kill the whole PID tree (Windows zombie risk)
}

interface ToolProposal {
  correlationId: string | number; // claude: SDK callback handle / MCP id | codex: JSON-RPC id | gemini: JSON-RPC id
  kind: "command" | "edit" | "read" | "other";
  raw: unknown; // tool args: command[]/string, file path + diff, etc.
  agentNativeOptions?: unknown; // gemini options[] (echo one optionId back); codex decision enum; claude behavior
}
```

### How each protocol maps onto it

| Adapter primitive   | **claude** (PATH A SDK)                                                                                                      | **codex** (app-server)                                                                                                       | **gemini** (ACP)                                                                                                                 |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |

| `events()`          | NDJSON lines: `assistant`/`user`/`result`/`system/*`                                                                         | JSONL notifications (`thread/started` + item events)                                                                         | `session/update` notifications (`agent_message_chunk`, `tool_call`, …)                                                           |
| **`tool_proposed`** | **`canUseTool(toolName, input, ctx)` invocation** (SDK pauses here)                                                          | **`item/commandExecution/requestApproval`** / **`item/fileChange/requestApproval`** server→client request                    | **`session/request_permission`** server→client request                                                                           |
| `decide('allow')`   | `return { behavior:"allow", updatedInput }`                                                                                  | `{ result:{ decision:"accept" }}` on matching id                                                                             | `{ result:{ outcome:{ outcome:"selected", optionId:"proceed_once" }}}` on matching id                                            |
| `decide('deny')`    | `return { behavior:"deny", message }`                                                                                        | `{ result:{ decision:"decline" }}` (continue) / `"cancel"` (stop turn)                                                       | `{ result:{ outcome:{ outcome:"selected", optionId:"cancel" }}}`                                                                 |
| `decide('modify')`  | **`return { behavior:"allow", updatedInput:<mutated> }`** — only claude supports true in-place rewrite                       | **unsupported** → `decide('deny')` + `steer()`                                                                               | **unsupported at permission layer** → rewrite bytes at `fs/write_text_file`/`terminal/create` reverse-request, or deny+re-prompt |
| `steer()`           | next NDJSON user message on stdin                                                                                            | `turn/steer`                                                                                                                 | next `session/prompt` (or `session/cancel` first)                                                                                |
| worktree isolation  | `cwd` + `--add-dir`; `acceptEdits` naturally bounds to cwd                                                                   | `cwd` in `thread/start`; `sandbox:"workspace-write"` confines writes                                                         | `cwd` in `session/new` (+ `--include-directories`)                                                                               |

**Three load-bearing asymmetries the adapter must encode, not hide:**

1. **`modify` is claude-only.** Only claude's `canUseTool` returns a mutated `updatedInput` that silently replaces the executed input. codex and gemini are **gate-only** at the approval layer. A portable tower must either (a) expose `modify` only for claude and degrade to deny+steer elsewhere, or (b) drop `modify` from the common interface and do all rewriting via deny+steer. **Do not pretend a uniform `modify` exists.**
2. **Fail-open defaults differ and are silent.** claude raw-stream **auto-executes** with no handler; gemini **auto-executes** under `yolo`/`auto_edit`; codex falls back to its `approvalPolicy` if the harness forgets MCP `elicitation`. The adapter's `start()` must **fail-closed**: refuse to spawn without a registered handler / with yolo / without `elicitation`, and run a deliberate **deny-test** before trusting the gate.
3. **Correlation discipline.** Every `tool_proposed` carries an id (SDK callback handle / JSON-RPC id). Forgetting to answer one **blocks the agent's turn forever** (explicit Windows-hang note for gemini; same for codex). The adapter must guarantee exactly-one response per id.

### Mandatory startup gate (applies to all three, encodes Risk #1)

Before the tower trusts any agent's gate, run a **deliberate deny-test**: spawn in a scratch worktree, drive a turn whose first action is a guaranteed-gated write/command, and assert the agent (a) **emits the approval request**, and (b) **does not execute** when the tower replies DENY (claude `behavior:"deny"` / codex `decline`|`cancel` / gemini optionId `"cancel"`). If the action executes anyway, **the gate is a no-op — abort, do not dispatch real work.** This is the single check that catches every silent fail-open mode above.

### Recommended build order

**Prove mediation live in this sequence — strongest-evidence-first, so each step de-risks the next:**

1. **codex `app-server` FIRST.** _Why:_ its contract is the **most verified** (binary-emitted JSON-RPC schema — highest trust of the three), and a server-initiated request with required `id` is the cleanest mediation model. One live `app-server` probe (Risk #5 probe in §3.2) converts "schema-proven" → "behavior-proven" and gives the tower a reference implementation of the request/response correlation loop. _Carry-over:_ the JSON-RPC id-correlation + blocking-reply loop is reused almost verbatim for gemini ACP.

2. **gemini `--acp` SECOND.** _Why:_ same JSON-RPC-over-stdio shape as codex (reuse the transport + correlation code from step 1), and the contract is bundle-verified — but it has the **highest count of runtime-fatal traps** (fixed-enum optionId, fail-open yolo, `always` blindness, missing-field toolCall). Do it second so the deny-test harness from step 1 is already in place to catch them. One live round-trip (§3.3 probe) confirms the optionId echo end-to-end.

3. **claude LAST, via SDK PATH A.** _Why:_ it's the **odd one out** (SDK callback, not JSON-RPC stdio) so it shares the least transport code, and its raw-CLI mediation (PATH B) is the **least verified** piece in the whole report. Building it last means: (a) you adopt the **verified** SDK `canUseTool` path and skip the unverified raw frame entirely; (b) if PATH B is ever needed, the stdio-MCP-logging probe (§3.1) runs against a tower that already has a working deny-test from steps 1–2. **Do not** ship the raw `control_request` path on third-party shapes.

**One-line rationale:** verify the agent whose contract is hardest-proven first (codex), reuse its transport for the structurally-identical-but-trap-heavy one (gemini), and finish with the architecturally-divergent one on its _verified_ SDK path (claude) — converting every "schema/static-proven" mediation into "behavior-proven" before a single line of real orchestration runs through it.
